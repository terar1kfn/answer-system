# Native route dependency review (0.31; validation deferred)

A diagnostic guide may traverse local questions, CASE targets (first native question, or solution if questionless), SOLUTION targets (explicit direct resolution), and native escalation. Reviewing only the first guide is insufficient.

The inspector walks the bounded reachable graph and returns metadata, exact full-record fingerprints, the source/catalog and owner pin, the original mapping-row fingerprint, the option-to-destination edges, and a deterministic route fingerprint. It does not return procedure text or execute any native action. It reports missing and disabled destinations, cross-owner and unauthorized procedures, incomplete bilingual structures, high or unrecognized risk, unavailable/unreviewed dependencies, native entry menus, history-dependent BACK/custom-entry operations, unrecognized destinations, excessive graph size, and forward cycles as blockers. Medium risk, explicit diagnostic-skipping SOLUTION links and escalation are separately identified for review. An intentional native branch is not automatically unsafe, but a supplemental mapping cannot use a branch that has not been independently reviewed.

The existing reconciliation report now includes these route-review records for retained candidates. A candidate with route blockers remains a review artifact, not an eligible release. Use inspectNativeGuideRoute before preparing a release. Every per-row approval must include routeFingerprint and routeDependenciesConfirmed=true; the trusted verification callback receives the exact review. Release preparation rejects blocked branches. Its payload contains routeReviews. The approved provider refuses releases missing these records, rechecks their fingerprints, exact native catalog/owner/dependency pins, mapping and approvals, and still requires the host's verified activation record. Prior release formats require renewed review; do not fabricate an approval or reuse a stale route fingerprint.

The host remains responsible for checking authorization and availability during actual native navigation and retaining protected exam/account/academic-integrity routes. No institutional guide contents or identifiers are stored in this public package. No runtime, test, build, native integration or deployment validation was performed.
