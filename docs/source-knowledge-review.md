# Source-grounded gap review and diagnostic discrimination — 0.22

The private knowledge gap pack is a review format, not a published catalog. It is pinned to the actual native configuration revision and canonical fingerprint. Each bilingual draft identifies service/purpose, proposed new/revised procedure or referral/policy review, exact existing native IDs if relevant, fixed prerequisites, applicability, source-linked steps, limits, and outstanding reviewer questions. The public package contains no private university procedures or IDs.

Each source is explicitly classified as institutional or vendor guidance, and includes a precise HTTPS reference and access date. An institutional requirement must have an institutional source; vendor material alone cannot create a campus policy. An institution domain or a valid URL is not itself proof that a claim is current, correct or applicable. The host must separately check the actual source and each associated claim. The review wrapper requires authorized native staff, checks permission for each proposal, rechecks the actor and source catalog after review, and returns only a draft for independent applicability review and native editor/publication. It cannot write or activate any guide.

The diagnostic engine now distinguishes an explicit forgotten-password request from changing a known password and from unavailable MFA methods. A usable registered method does not imply Security info is accessible; ask before offering a reviewed method-management guide. Missing notifications may request a matching approved guide only after reported credential acceptance and working connectivity.

Academic-portal troubleshooting identifies the affected system, distinguishes the mobile learning application's site configuration from account/MFA failure, and separates standard, Turnitin and lecturer-approved large-file link submissions. Request creation/status guidance is specific to an online request system, not course registration. Attendance QR context distinguishes campus entry from an instructor-provided QR activity and location permission from camera or Bluetooth permission. Mail sync/calendar guidance checks app-only scope and may use client-specific prerequisites; meeting guidance may distinguish desktop, mobile and web. No vendor procedure is inferred to be an authorized campus procedure. Protected routes, availability and the exact native guide mapping remain authoritative.

New guide purposes are available for independent private mapping; a missing or ineligible mapped guide still results in native support rather than fabricated instructions. No tests, syntax checks, model calls, builds, publication, live import, or private-host edits performed.
