# Automated private knowledge-quality review (0.40; validation deferred)

The new deterministic auditNativeKnowledgeQuality and createNativeKnowledgeQualityReviewer modules consolidate existing native catalog projection, route inspection and knowledge backlog into an actionable private review report. The report is advisory; it is not a replacement for native knowledge management or publication approval. No model is needed, no network is contacted, and no procedure is generated or changed.

## Staff integration and scope

Import the new answer-system/knowledge-quality export on the trusted native server. createNativeKnowledgeQualityReviewer requires authenticate, mayReviewKnowledge, getInput and getReviewScope. Only an active INTERN, MANAGER or SUPER_MANAGER with independent native permission may request the report. The remaining callbacks getSourceReviews, getMetricRows and getEffectivenessRows optionally provide trusted scoped snapshots; defaults are empty arrays. Do not accept those records or staff permission claims from a browser. No endpoint, storage, cron job, editor or live UI is included.

getInput supplies the existing projectNativeCatalog contract (published configuration, current mapping, exact native service IDs, diagnostic scope and trusted eligibility/ownership hooks). getReviewScope returns {allowedGuideIds, completeServiceIds}. allowedGuideIds is an explicit independent staff authorization list including scoped missing mapped references if the reviewer may reconcile them. completeServiceIds is optional in meaning but must be an array (use [] for partial scope); only designate a generic service as complete if the host authorizes full review of all relevant mapped native owners and their guides within the reporting scope, plus full aggregate scope. The audit verifies included mapped and uniquely owned ordinary guide references for claimed complete services; this cannot prove the host has disclosed all authorized data. Exam and directory stay native-only. Partial scope may show individual guide issues, but must not infer coverage of an entire service. The original published mapping and guide bodies are never returned or changed.

The native host must rate-limit requests, provide immutable consistent snapshots, enforce exact staff and reporting scopes in every callback, and recheck the returned report pins before use or display. Reviewer authenticates before and after two independent snapshots and rejects differing report fingerprints; no long-running background jobs. Scope is bounded to 250 inspected guide references per report (select a narrower review scope if exceeded), 3,000 unique findings, and 512 theoretical prerequisite combinations per service/purpose. The report explicitly flags finding truncation and conditional-enumeration limits. Scope pins and data fingerprints are not publication signatures. Invalid base mapping/configuration may fail closed in the existing projection rather than produce a report.

## Findings and interpretation

- Structural: missing or withheld mapped guides, unpinned mapping, incomplete bilingual title or steps, invalid questions/choices, repeated exact step text, duplicate option labels, native route blockers and review notes, reachable-graph inspection and potentially unused questions. Route review inspects current guide bytes with an inferred current entry, not approval of the historical mapping. Non-authorized dependencies are not disclosed; a scoped generic dependency-review signal is returned. Native-only/privileged or unavailable procedures are not inspected as ordinary self-service.
- Similarity: identical whitespace-normalized bilingual title or procedure text within an exact native owner; potentially conflicting admitted guides with satisfiable overlapping fixed prerequisite sets and no strict specificity ordering. Duplicate text is a review lead, not equivalence; intentional shared steps and different applicability can be valid. No semantic contradiction or factual accuracy claim is made. The engine's existing specificity selector is unchanged.
- Coverage: for explicitly complete service scopes only, report known guide purposes without an admitted procedure, theoretical combinations of fixed question options not covered by conditional mappings (bounded product excluding unknown/not_tried), and prerequisite questions that are not in the generic automatic discriminator list. Theoretical combinations can be impossible or resolved by native routing; this is not proof of a real gap or actual question reachability. Current overlapping reviewed-context patterns and stale context pins are flagged for independent review, not accepted as learning.
- Freshness: independently host-verified metadata records use exactly {guideId,guideFingerprint,checkedOn,reviewDueOn,sourceStatus}. Dates are real UTC calendar days; checkedOn cannot be in the future, due date cannot precede check. sourceStatus is verified_current, changed, unavailable or unverified. Missing or stale exact-version records, due dates and externally reviewed source status become review leads. The module never fetches sources, invents review dates, decides a procedure is obsolete from age alone, or treats a URL as proof.
- Operational: reuse the existing knowledge backlog's minimum-group aggregate gap events, restricted to complete service scope, and exact current guide/source/route-pinned single-guide staff-verified known outcomes (at least 10 known, at least 3 unresolved, unresolved fraction >=35%, minimum group respected). Student-only reports, legacy unverified routes and mixed interventions do not qualify. Counts are events/outcomes, not unique students or causal estimates.

Output is private metadata: fixed finding code, severity category (blocker means a structural review blocker, not a live incident), exact permitted guide/owner IDs and guide fingerprints, fixed detail IDs, bounded counts, review action, source/catalog/mapping/scope pins, deterministic report fingerprint and explicit human-review/no-publication flags. No titles, raw step/question/option text, raw sources, student data, case/reviewer identities, generated procedures, private comparison text hashes or out-of-scope dependency IDs. The native staff UI may retrieve current authorized titles from the host separately. No automatic fix, approval, publication, ranking adjustment, or route change.

## Deferred validation

Use synthetic-only fixtures: complete and incomplete bilingual procedures, disabled/privileged/native-only paths, malformed or stale mapping, missing target/cycle/unreachable question, cross-scope dependencies, exact duplicate vs intentional shared steps, strict containment vs overlapping/disjoint conditions, combination cap and truncated report, partial versus complete review scope, expired/missing/stale source review records, current and stale context patterns, exact route-verified vs mixed/student-only/stale outcomes, suppressed small groups, unauthorized staff and mid-review changes, no private text leakage, deterministic reports, and prior engine/backlog regression. No tests, syntax checks, builds, models, private data import, deployment or host modification have been performed.
