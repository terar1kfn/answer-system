# Reviewed contextual guidance — 0.16 (validation deferred)

The engine has an optional private, revision-pinned layer that can use structured knowledge derived from previously resolved IT cases. This is not automatic training on raw tickets, a vector-neighbor answer, or a substitute for approved institutional procedures.

The deterministic diagnostic route first selects the service, guide purpose and required conditions. If several approved guides remain tied at the highest matching prerequisite specificity, a reviewed contextual pattern can help distinguish them. It may only select among those exact eligible guides. It cannot introduce a new service, different purpose, account action, policy exception or unapproved guide. It is disabled for safety/exam/identity and restricted contexts.

A pattern contains fixed option IDs: an actual operation anchor plus at least one domain-appropriate context discriminator, exact guide ID, purpose, source revision, opaque case reference, author and independent reviewer, verified-outcome marker and optional guide fingerprint. Raw transcripts, passwords, free-form evidence and numerical confidence are not supported. Patterns must match all required observations. Contradiction eliminates a candidate; missing information does not count as confirmation.

When competing patterns suggest different guides, a safe unasked platform/browser/mail-client question may be requested only if the available patterns specify different answers to that question. If several conflicting patterns fully match, or a competing incomplete pattern cannot be safely distinguished, the engine abstains instead of guessing. The original prerequisite and offered-guide repetition checks remain authoritative.

The native catalog projection withholds a pattern if its guide is no longer eligible, its exact guide fingerprint changed, or its source publication revision changed. Active published pattern metadata contributes to the catalog revision, invalidating stale sessions when it changes. Private configuration must be kept outside this public repository.

The case-to-context draft function requires an independently verified resolved-case record, exact current eligible guide and fixed observations present in the case. A separate reviewer may prepare an approved candidate against the same catalog revision; neither function publishes or writes it. The private host must enforce actor permissions, independently verify case/outcome provenance, review guide suitability, and explicitly activate the candidate through the existing knowledge publication workflow. The optional pattern has no effect until that happens.

No actual case records or guide mappings have been imported. No tests, syntax checks, builds, browser runs, provider calls, deployments, or private repository changes were performed.
