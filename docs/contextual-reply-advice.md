# Optional contextual reply interpretation — 0.18 (validation deferred)

The native bridge can optionally use a local advisory model when a student's typed reply cannot be deterministically interpreted. It is off by default and requires both a configured trusted server-side replyAdvisor and the current native policy's explicit allowModelAdvice flag. The host must approve the provider, local-only deployment and privacy controls. This is not automatic activation of the existing university model.

The advisor gets the one canonical pending question, its allowed option IDs and fixed labels, admitted generic service IDs, at most eight prior fixed non-sensitive observation labels, and the bounded current reply. It receives no previous raw chat, guide bodies, user identity, ticket content, account state or privileged host tools. Best-effort screening rejects detected secrets, protected topics, recognized error codes, obvious instruction-injection phrases, unrelated service mentions and explicit observation conflicts. This is not a full data-loss-prevention guarantee.

An allowlist restricts the advisor to ordinary diagnostic context questions. It does not advise on approval prompts, registered MFA methods, account credentials, error confirmation, exam state, factual topic selection, recovery completion or whether a problem is resolved. The existing deterministic path, protected native routes and reviewed error-confirmation logic retain precedence.

The provider uses a structured option-ID plus quote response, or an abstention. An independent validator requires an allowed option and a contiguous supporting quote present in the current reply. A quote does not prove semantic entailment. The model never advances the state, chooses a guide, performs a recovery action or creates a ticket. Only the student's deliberate selection of an existing option advances the normal engine. The quote is not retained or returned to the client.

The bridge returns a clarification effect with a bounded suggestion ID, tied to the unchanged current question/version. It rechecks authentication, catalog revision, scope, feature enablement and model-advice policy after inference. The native client controller validates the suggestion against the displayed options. The host may highlight that option, but must not automatically click or submit it. A missing, invalid, conflicting or unavailable suggestion returns ordinary clarification. Inference is single-flight with a bounded timeout and at most four attempted advisory calls per issue; the host must enforce additional visit/service-wide quotas.

The Ollama adapter targets the configured loopback port and does not follow redirects, download models or start services. The host must independently ensure that its local service/model cannot proxy private input to external inference. No provider is configured or called by default. No raw input or private institutional data was added to this public repository.

No tests, syntax checks, builds, browser execution, model inference, live deployment, or private application modifications were performed. Deferred validation includes bilingual paraphrases, ungrounded quotes, contradictory evidence, protected input, policy revocation, timeout/late responses, state/version isolation and explicit confirmation.
