# Session and architecture optimization — 0.44 (validation deferred)

## Native projection and engine reuse

createNativeCatalogEnginePool({maxEntries:8,now}) uses a per-instance LRU (0–32 entries). Its project(input,{incidents}) always performs the full native catalog projection and current eligibility/ownership hooks before looking up the exact derived catalog and incident fingerprints. Cache misses validate the catalog via createEngine and create one engine; hits reuse the validated immutable engine. The standalone projectNativeCatalog API still validates every projection. No native authority, current host configuration, user credentials, visit state, raw text or model payload is cached. A cached engine retains bounded scoped catalog metadata and minimized confirmed incident records, so keep the pool server-private. clearAll also clears the pool. This saves duplicate engine validation/reconstruction, not all projection/hashing costs; no benchmark or measured performance claim.

The embedded bridge resolves current native policy, configuration, approved mapping and incident scope on every relevant command/recheck. Confirmed incidents are reduced to id, serviceId, status, authority, updatedAt and expiresAt; unauthorized, expired or unconfirmed records are excluded. The incident fingerprint is part of the session pin. Any eligible incident-set change requires a new diagnosis; an expired displayed incident retains the dedicated INCIDENT_REFRESH_REQUIRED behavior. Time-sensitive incident predicates still run at decision time. Native host must bound incident queries and independently authorize their scope.

## Visit lifecycle and history

maxVisits now bounds the union of retained visit rows and in-flight locks, including new visits still resolving policy. No active visit is evicted to make room. All dispatch and diagnostic capture operations use the same visit lock; capture is a read-only trusted hook and cannot overlap a student mutation. Lifecycle cancellation marks outstanding locks and aborts advice; the bridge rechecks authorization, current policy/catalog pins and visit identity before effects are returned. Native guide/ticket effects remain native and must be checked by the host immediately before use.

forgetVisit and clearAll are native lifecycle hooks, not student commands; never reuse a visit ID after native expiry, termination, sign-out or restart. The host must coordinate one authoritative worker per visit or use a future durable session adapter. In-process maps are not a multi-worker/distributed state store. expireIdleIssues({idleMs}) is an optional trusted sweep (1000–86400000 ms), invoked by the host if desired. It clears idle issue evidence only if no command holds that visit's lock; retains the owner and increments version, avoiding resetting an active visit to zero and accepting stale commands. Host remains responsible for removing tombstones with forgetVisit once actual authorization ends. stats() returns only counts, not personal data. No interval/timer is installed for visit expiry.

Undo is deliberately conservative. Native guide launch is an irreversible boundary for the supplemental history, even if the user has not completed the guide; launching clears undo history, and a guide-outcome transition cannot create a snapshot that crosses that boundary. Recovery remains a separate irreversible boundary. Later reversible diagnostic answers retain exact evidence, answers and guide-return snapshots. Undo restores that coherent snapshot with a monotonically advancing engine turn, not an external action or claimed undo of a native guide or ticket. An existing native draft effect is not a submitted ticket; native request identity remains authoritative.

## Local inference resources

createAdviceCoordinator({maxConcurrent:1}) accepts 1–8 actual concurrent invocations. run(task,{signal,timeoutMs}) gives the task an AbortSignal and returns completed/value, busy, timeout, cancelled or unavailable. No queue, retry, arbitrary command, model startup or background schedule. Timeouts/cancellation stop waiting and signal abort; they do not falsely free the lease of an underlying task that ignores abort. Lease is released only when that invocation settles. A hung worker must be recovered by the authorized host; do not bypass concurrency with new coordinators.

Share one provider coordinator among createDiagnosticIntakeAdvisor, createContextualReplyAdvisor and createScreenshotAdvisor to bound actual local provider work. Each advisor retains its single-flight guard, existing safe fixed-choice preparation/validation and independent timeout; disabled remains default. The bridge separately bounds injected advisor invocations using its own adviceCoordinator and adviceTimeoutMs (default 35 s). These must be distinct coordinator instances to avoid nested lease deadlock. A visit cancellation aborts the outer request, built-in advisors forward cancellation to providers, and all suggestions still need explicit student confirmation. Rejected/late results are never applied. A custom trusted adapter must respect abort, privacy and retention; actual provider execution cannot be forcibly stopped by JavaScript. Temporary screenshot copies are zeroed on settlement where possible; base64/provider copies are not guaranteed erased. No real screenshot/model or cloud call. Multi-process/provider-global limits must also be enforced by the host.
