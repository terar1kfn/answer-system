# Private catalog reconciliation — 0.21 (validation deferred)

The live native host remains authoritative. A source checkout, cached browser catalog or previous export is not proof of a live revision. A mapping draft is not an active mapping. Read-only private reconciliation takes a current authorized native configuration, a previously pinned mapping and optionally its exact baseline snapshot. It never fetches credentials or publishes a revision.

The result separates an identical snapshot, a newer revision, rollback, and content drift under the same revision. Compare exact guide IDs, canonical record fingerprints, entry mode, service ownership, availability, reviewed labels, audience, self-service permissions, bilingual procedure completeness and explicit reviewer holds. Changed guide contents are never silently repinned. With a supplied matching baseline, detect added/removed/changed services and guides; a changed service requires review. Without the baseline, complete inventory differences are explicitly unavailable. A same-revision content mismatch or rollback produces no candidate mapping.

Only unchanged, currently eligible rows are carried into a new PRIVATE candidate, not approved for use. The current entire catalog is pinned and all previous reviewed-case patterns must be independently rebased. New IDs are surfaced as unmapped, never automatically assigned or enabled. Require independent applicability review and host-side activation at the exact publication revision. No report proves current live provenance; an operator must establish how and when the snapshot was obtained.

A conservative offline snapshot policy takes explicit legacy available-service IDs, reviewed source labels and extra entry-menu IDs from an authorized reviewer who inspected the native host. It requires explicit native guide ownership or a unique category across *all* services. This is an offline review aid, not a permission decision. The actual host policy callbacks remain authoritative. The optional local command reads only bounded private JSON files and writes a new, exclusive report outside the repository; it performs no network access or automatic publication. Its request document contains currentCatalogPath, mappingPath, optional baselineCatalogPath, policy, allowedNativeServiceIds, diagnosticServices and options (nextMappingRevision, optional holds as guideId/reasonCode pairs). Never pass private output to the public repository.

The native bridge now delegates to existing native routing if its pinned mapping is stale, after checking that the authenticated visit is still current. Student-facing behavior must never apply a stale guide or automatically submit a support request because a catalog was republished.

No real live snapshot was fetched or reconciled by this implementation, and no tests, syntax checks, builds, provider calls, deployment or private-host changes were performed. These are implemented review mechanisms with validation deferred.
