# Controlled reviewed-context publication — 0.43 (validation deferred)

The independent contextual release mechanism closes the architectural gap between the learning report, verified cases, reviewed-context candidates and the embedded diagnostic engine. A favorable aggregate proposal or review disposition is not a publication approval. Staff retrieve and independently verify individual cases supporting the proposed exact pattern before preparing a release. The coordinator reuses prepareReviewedContextDraft / approveReviewedContextDraft and the current deterministic selector; it never trains a model, writes a native procedure, changes a base mapping, or grants a new permission.

## Architecture and scope

The existing approved mapping release remains immutable and context-free. createContextualMappingProvider (answer-system/context-release) wraps createApprovedMappingProvider. Provide getConfiguration, getActiveRelease and verifyActiveRelease with their existing authoritative native contracts, plus getContextHead, verifyContextHead and verifyActiveContextRelease. Use the returned function as getMapping in the existing embedded bridge only after native integration. The plain approved provider rejects nonempty context fields, so it cannot substitute for this separate release.

getContextHead(actor) returns the durable global (or independently scoped publication namespace) head, exactly {sequence,release,revokedPatternIds}. Initial head: {sequence:0,release:null,revokedPatternIds:[]}. sequence must strictly increase on every committed publication change; never reuse a sequence, even after revoke-all or restoration. Active release is exactly {kind:'native_context_release',status:'active',activationRef,payload,releaseFingerprint}; the native authority constructs it ONLY inside the activation transaction from a real verified candidate. The payload has releaseId, authorRef, reviewerRef, baseMappingFingerprint, sourceRevision, sourceCatalogFingerprint, ruleVersion, expectedHeadFingerprint, expectedSequence, restoredFrom, entries; each entry has pattern, evidenceFingerprint and routeFingerprint. No actual records are included here. The host verifies its durable head, even if empty, via verifyContextHead({actor,head,headFingerprint}); this must compare against the real current state, sequence, activation, revocation history and access, not a supplied Boolean. verifyActiveContextRelease({actor,releaseFingerprint,activationRef,headFingerprint,patternIds}) independently verifies the actual activation, exact active pattern set, current authority, case corrections/invalidation and policy. Only true permits consumption. These server callbacks may work for a student visit without exposing private records or staff-only data to that visitor.

The provider checks the base and head twice and verifies current active authority. A stale base/source/rule pin disables all contextual patterns; it does not transplant them to a new guide version. The derived mapping revision includes the exact base and head fingerprints, including empty/revoked states. Changes invalidate old diagnostic catalog pins and sessions. If head or authority cannot be verified, CONTEXT_RELEASE_UNAVAILABLE delegates to native routing and clears obsolete supplemental state. The original host still projects by current exact student scope and authorizes native guide opening. The engine restricts context disambiguation to same-native-owner tied guides, and all deterministic prerequisite, protected and repeated-guide checks remain. No raw case text or evidence fingerprint is included in student effects. Keep the derived mapping on the server; it is not an independently approved base mapping and must never be passed to the base release preparation workflow.

## Native publication coordinator

createContextReleaseCoordinator uses the same read hooks and authenticate, mayManageContext(actor,action), getReviewInput(actor), getCaseEvidence, verifyCaseEvidence, getDraft, verifyDraft, getApprovedCandidate, verifyApprovedCandidate, getHistoricalRelease, verifyHistoricalRelease and commitContextHead. Every callback must use real native authorization and records, immutable consistent snapshots and a single publication namespace. Active staff role is necessary but not sufficient. Manager/Super Manager is required for activation/revocation; the author must be different from the independent reviewer and from the activation actor. A reviewer may activate only if separately authorized as manager. All staff actions must respect private publication scope. getReviewInput returns the existing full authorized native projection contract with actual configuration and eligibility/owner hooks; the coordinator substitutes the independently approved base mapping. Reject incomplete review scope rather than infer ties from omitted guides. Bound releases to 100 selected patterns. Conflicting overlapping patterns targeting different guides within a service/purpose are rejected, even if a third candidate might resolve the overlap. The full approved mapping is inspected for an actual matched tie (not a pending prerequisite), all tied guides must have the same exact native owner and unblocked current routes.

1. status(credential) returns sequence and head/base pins, stored and currently source/rule-pinned pattern counts, and revoked IDs for authorized staff. Pinned count is not a claim of actual live usability or evidence verification.
2. prepare(credential,{releaseId,expectedHeadFingerprint,selections}) prepares a **full replacement** release draft, not an incremental patch. Each selection is {patternId,caseRef,purpose,match}. IDs/references must be opaque native metadata, never actual student identities. A current stored pattern to be retained must be explicitly selected and independently re-reviewed, not silently inherited. getCaseEvidence({actor,caseRef}) returns {caseRecord,evidenceFingerprint}, a minimal approved resolved-case record compatible with the existing reviewed-context draft function and an authoritative private version fingerprint. verifyCaseEvidence({actor,caseRecord,evidenceFingerprint,pattern,sourceRevision,routeFingerprint,ruleVersion}) independently checks finalized isolated single-guide staff-verified resolution, original pre-attempt observations, exact historical published guide/route, authorized scope, corrections/revocations and current applicability. Historical rule version is evidence, not a claim that a prior outcome happened under the current engine. The host must verify relevance of any historical rule differences. A case record or hash alone is not proof. The draft only retains the fixed selection, draft pattern and fingerprints, never raw case contents. Aggregate learning proposal dispositions can initiate this process but cannot bypass it. Native host durably saves an authorized still-current draft and real author.
3. review(credential,{draftRef}) reads the real draft via getDraft({actor,draftRef}), verifies stored identity/status via verifyDraft({actor,draftRef,draft}), independently rechecks the exact cases, current route and catalog/head pins, and approves each pattern using the existing independent reviewer function. Returns an inactive native_context_release_candidate with exact payload and releaseFingerprint; host stores independently authorized candidate and review record. No student route changes.
4. activate(credential,{candidateRef,operationRef,expectedHeadFingerprint}) loads a real stored candidate with getApprovedCandidate({actor,candidateRef}), verifies exact review with verifyApprovedCandidate({actor,candidateRef,candidate}), checks current evidence and pins twice and rechecks authority. Requests a durable native transaction via commitContextHead; success is reported only after verifying actual current head/readback and active release. No candidate can activate itself.
5. revoke(credential,{patternId,operationRef,expectedHeadFingerprint,reasonCode}) requests immediate authorized removal of one currently included pattern, or all with patternId:null. Fixed reason codes: evidence_corrected, scope_changed, conflict, source_changed, safety_review, administrative_review. Individual revocation adds the ID to head.revokedPatternIds; revoke-all sets release:null and revokedPatternIds:[]. Neither changes the base mapping nor requires proving that a bad case is still valid. Maintain a separate native emergency disable/revocation capability independent of base availability or this coordinator.
6. prepareRollback(credential,{releaseId,expectedHeadFingerprint,historicalReleaseRef}) loads and verifies the actual historical active release via getHistoricalRelease / verifyHistoricalRelease, requires the same current exact approved base/source, and builds a new full replacement draft from the historical selections. RestoredFrom records the original release fingerprint, not an activation token. All cases must still verify and the new rule version, author, independent review, manager activation and next sequence apply. An old release object is never directly reactivated. Host verification must reject any previously revoked case/pattern whose underlying problem remains unresolved. If restoring a subset, prepare an explicit replacement instead.

## Durable transaction (mandatory host integration)

commitContextHead receives {actor,expectedHeadFingerprint,expectedSequence,baseMappingFingerprint,nextSequence,change}. change is {kind:'activate',operationRef,candidateRef,releaseFingerprint}, or {kind:'revoke_pattern'|'revoke_all',patternId,operationRef,reasonCode}. Within one authoritative transaction the host must reauthenticate current actor and reauthorize action and scope, verify current base/source and exact expected head/sequence, verify the saved candidate and independent review/author/activation constraints plus current evidence for activation, reject reused release IDs, persist the new head and immutable audit/history record, deduplicate operationRef and enforce that only the selected candidate or specified removal changes. Activation constructs the active envelope with a real native activationRef, sequence increments exactly once and revokedPatternIds resets to []; revocation retains the original exact release or clears it as described. Result is exactly {status:'committed',headFingerprint,sequence}, returned only after confirmed durable commit. The coordinator reads the verified current head again and checks the mutation. On timeout, thrown error, concurrent update or CONTEXT_COMMIT_UNCONFIRMED, the host must reconcile by operationRef and authoritative audit history before allowing another action; never blindly retry. This library has no database, endpoint, background job, real staff identity, live case adapter or native transaction implementation. Host owns durable state, idempotence, authorization, recovery and audit retention; do not simulate authority using candidate flags.

## Deferred validation

Synthetic cases only: correct full base approval and independent author/reviewer/activator; incomplete staff scope, protected/mixed or corrected cases and unconfirmed observations; exact product/owner, current route and true tied selector; overlapping patterns; candidate/draft tampering; unauthorized actor/transaction; base/rule/head change and race; activation readback and uncertain delivery; individual/all revocation with stale cases; rollback stale source or still-revoked evidence; monotonic versions and no replay; invalid empty/active head; consumer authority revocation; ordinary native fallback and prior session invalidation; no raw case leakage and regression of existing base releases. No tests, syntax checks, builds, AI execution, actual native hooks or deployment performed.
