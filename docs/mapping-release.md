# Private reviewed knowledge release — 0.25 (validation deferred)

A source-backed knowledge proposal is not a published guide. A reviewed proposal is not a mapping approval. A mapping approval is not host activation. The new integration layer connects these stages without granting the public package authority over the native application.

1. Import and review private source proposals using the existing source-knowledge review module. Its source findings are attributable to the native reviewer and pinned to the original proposal content.
2. A qualified native reviewer inspects the actual newly published guide, the original proposal, source verification, exact service ownership, applicability, permission and current published fingerprint. The native host must independently verify this publication decision.
3. preparePublishedKnowledgeMappings builds a candidate mapping addition only for self-service new/revised guide purposes with a current exact native owner and eligible native guide. Referral/policy review items cannot become student procedures. It requires a mapping already reconciled to the current full catalog. Existing mappings cannot be silently replaced; mapping changes use explicit private review. The original native diagnostic entry mode is retained.
4. prepareMappingRelease requires an independently reviewed per-row approval for every included mapping, with exact row and guide fingerprints, source/applicability/permission confirmation, an independent release reviewer, and current native projection eligibility. It returns an inactive release candidate. It does not write, publish or activate anything. Reviewed case-context patterns need a separate release review.
5. The private host authorizes and persists an active release outside this package. createApprovedMappingProvider verifies its exact payload fingerprint, per-guide content, current source pin, active/revocation state and a trusted host activation record. Supply this provider as getMapping in the real embedded bridge. A stale or unavailable approved mapping delegates to the existing native workflow. Normal current user scope and native permissions still apply.

No source truth is established by a fingerprint or approval flag alone. The host must verify authorization, source claims, publication, independent reviewer identity and activation state using authoritative records. Do not construct an active envelope from a candidate just to satisfy the schema. No institution mapping, real approval or private guide content is included in the public repository.

Previously successful case-derived pattern preparation also requires an explicit resolved outcome and the exact current native guide fingerprint; a staff label alone is insufficient.

This implementation has not been run. No live catalog was imported, no real proposals or mappings approved, no tests/builds/provider calls executed, and no private host files changed.
