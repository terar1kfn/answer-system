# Conditional solution planning (0.36; validation deferred)

Within a deterministic service and purpose, compare reviewed guide constraints by logical containment, not by count. Prefer a strict subset of allowed applicability only after all of its prerequisites are reported. Distinct incomparable guides are not ranked arbitrarily; existing independently reviewed context can disambiguate otherwise eligible candidates. Pending or explicitly uncertain prerequisites require a safe missing-evidence question or a review referral. Keep bounded candidate metadata for staff only, never raw input or native body. No numerical probability or automatic outcome-based choice.

The plan is rebuilt at each decision. It contains the original/current service scope, bounded attempted steps, explicitly observed transitions, current selection evidence and only the next authorized kind of action. It is conditional, not an executable queue. If general connectivity is explicitly restored but the original sign-in task still fails, or the same portal entry is explicitly blocked after guidance, renew the sign-in diagnosis and retain the original task and attempts. Clear stale access observations; retain staff-verified recovery provenance. At most two such transitions. The absolute turn limit, distinct alternative budget and host policy remain authoritative. An answer recorded before a stage reset remains available as the actual chosen fixed option in native journey output.

No project execution, tests, builds, deployments, model calls or private native host modifications performed.
