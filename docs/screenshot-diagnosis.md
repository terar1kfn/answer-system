# Optional local screenshot diagnosis (0.39; validation deferred)

This milestone adds an advisory visual path to the isolated answer-system library, not a public upload service or a deployed AU Assist feature. The ordinary native diagnostic route runs first; a screenshot can only supplement an existing current ordinary fixed question. The host must obtain explicit consent, screen the actual image for sensitive/protected content, and preserve native exact routes before permitting any model request.

## Host contract

- Inject createScreenshotAdvisor({enabled:true,provider}) into createEmbeddedAnswerBridge as screenshotAdvisor only when the host is ready. The policy must independently set allowModelAdvice and allowScreenshotAdvice to true. Both are pinned with the existing catalog/policy revision.
- The authenticated native UI may use requestScreenshotAdvice(screenshotRef) on the embedded client controller after its own upload and review flow. The reference is opaque (16–160 ASCII alphanumeric, underscore or dash characters). It is never a URL/path or embedded image. Dispatch checks the existing visit, actor, issue ID, expected version and current question. Native host owns the upload/consent UI, rate limits, request size limits, image disposal and access control.
- authorizeScreenshot({actor,scopeKey,issueId,expectedVersion,questionId,screenshotRef,phase}) must verify current visit ownership, unexpired consent, purpose, privacy screening, protected/exact-route policy and reference binding before use, again immediately before inference after receipt redemption, and after inference. Only true permits it. Authorization checks must be idempotent and work after one-use redemption, without transferring bytes again. Revoke consent/clear temporary data on logout, visit end or expiry.
- getApprovedScreenshot(binding) must atomically redeem a one-use receipt and return {screenshotRef,issueId,expectedVersion,questionId,consentVerified:true,privacyReviewed:true,protectedContext:false,routeKind:'supplemental',normalized:true,png:Uint8Array}. It must securely decode and re-encode to a metadata-free, non-interlaced, 8-bit RGB/RGBA PNG; review/crop/irreversibly redact names, IDs, email, account details, codes, QR images, URLs, notifications and other private pixels; block identity/MFA/security/exam/safety/uncertain contexts. Redaction must be reviewed before inference, not merely delegated to the vision model. Never accept client claims of approval or trust file extensions. If safe review is unavailable, disable the feature. The library checks PNG structure, size (2 MiB), dimensions (2048 per axis, 4 million pixels), no ancillary chunks/animation/trailers, but is not a decoder, CRC checker, OCR engine or privacy detector. Native decoding must enforce safe decompression and memory limits. Do not log or persist image bytes, receipt content, model prompts, or model responses. Delete native temporary files and disable provider prompt/image logging. Memory zeroing of a temporary buffer is best effort, not guaranteed erasure of copies.
- Optional createOllamaScreenshotProvider({enabled:true,model}) uses the existing bounded loopback-only Ollama transport and a host-selected local vision model that supports the structured response. The host must independently ensure that the server and model execute locally and never relay images externally. No model pull or service startup, no tools, cloud endpoint, redirect, free-form procedures, or external access is performed by this module.

## Inference and confirmation

Only visible ordinary current-question choices are offered: application/platform, current service, explicit feature/symptom, and a limited set of documented mail delivery signatures from ERROR_SIGNATURES. Unknown codes are not transcribed. The model may abstain, return one permitted option ID, or return one permitted documented error ID. A screenshot does not establish a root cause, a permission, an attempted step, a successful repair or the absence of a network. The response is strictly validated twice; it remains a hint, not evidence. Image instructions are untrusted and the host must not rely on the model to detect sensitive pixels or injection.

The bridge returns a transient clarify response and either suggestion or errorSuggestion with requiresConfirmation:true. The client presents the existing fixed choice for the student to select, or shows the predefined error code and asks the student to type it if it matches the current failed operation. Never automatically submit a choice or code. The normal respond path rechecks native routing and uses deterministic error confirmation/guide selection. No screenshot-derived state or suggestion is persisted. The advisor is single-flight, bounded timeout, at most three eligible requests per issue; rejected receipts count. No retry on uncertain transport. A host must also enforce visit/session rate limits, one-use expiry and multi-worker limits.

## Deferred validation

Validate synthetic fixtures only: image boundary/metadata/format rejection; invalid reference, consent, ownership and one-use redemption; protected context and native routing; policy/catalog/version change during inference, cancellation and visit termination; wrong/malformed/out-of-scope output and injection; visual uncertainty and abstention; explicit confirmation vs automatic evidence; ordinary documented mail error flow; request and concurrency budgets; English/Arabic copy; provider timeout/response size; regression of existing text-only and native guide flows. No actual uploads, local inference, tests, builds, deployment or live application changes performed in this milestone.
